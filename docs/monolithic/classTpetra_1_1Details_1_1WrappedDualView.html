◆ needsSyncPath()

template<typename DualViewType >
bool Tpetra::Details::WrappedDualView< DualViewType >::needsSyncPath ( ) const
inlineprivate

needsSyncPath tells us whether we need the "sync path" where we (potentially) fence, check use counts and take care of sync/modify for the underlying DualView.

The logic is this:

  1. If WrappedDualView tracking is disabled, then never take the sync path.
  2. For non-GPU architectures where the host/device pointers are aliased we don't need the "sync path."
  3. For GPUs, we always need the "sync path." For shared host/device memory (e.g. CudaUVM) the Kokkos::deep_copy in the sync is a no-op, but the fence associated with it matters.

Avoiding the "sync path" speeds up calculations on architectures where we can avoid it (e.g. SerialNode) by not not touching the modify flags.

Note for the future: Memory spaces that can be addressed on both host and device that don't otherwise have an intrinsic fencing mechanism will need to trigger the "sync path"
